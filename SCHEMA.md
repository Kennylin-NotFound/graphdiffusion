# Deployment Instance Schema

`DeploymentInstance` is the single static-data contract shared by instance
generation, deterministic evaluation, MILP construction, graph construction,
training, repair, and experiment reporting.

## Core dimensions

- `M`: number of unique microservices in the merged joint DAG
- `D`: number of edge devices
- `A`: number of applications
- `E`: number of dependencies in the joint DAG
- `R`: number of resource types

## Important modeling conventions

- Categorical placement uses global device indices.
- Every service has at least one compatible device on which its individual
  demand fits.
- Incompatible processing-latency entries are finite zero placeholders and
  must always be masked.
- `connectivity[d, d]` is false and `link_rate[d, d]` is zero. Colocated
  transmission is handled separately and has zero latency.
- Multi-hop forwarding and runtime contention are not represented.
- `link_rate` stores the effective direct-link rate corresponding to the
  denominator in the paper's transmission-delay expression; bandwidth and SNR
  do not need to be stored separately for deterministic evaluation.
- `dependency_data_volume[e]` is stored per dependency, but all outgoing
  dependencies of the same source service must have equal volume, matching
  the paper's `D_u^{tr}` assumption.
- `application_dependency_mask[a, e]` preserves each original application
  DAG before merging. The optimization objective still uses the joint DAG.
- `service_type_id`, `device_type_id`, and `application_type_id` are
  nonnegative dataset-global identifiers. They preserve generation provenance
  and provide stable categorical inputs for the future factor graph.
- Application weights are nonnegative and sum to one.
- Every saved instance is validated during construction, before saving, and
  after loading.

## Serialization

Instances are stored as compressed `.npz` files with JSON metadata embedded as
a non-pickled string. Loading uses `allow_pickle=False`. The save operation is
atomic within one filesystem.
